## Context
**What were you trying to accomplish?**

---

## Expected Behaviour
**What should have happened?**
Window rotation (LSN-20251111-003) would retry the failed operation on the new window ID, maintaining the same panel document context. The 6 PCB copies would persist across rotation.

---

## Actual Behaviour
**What actually happened?**
1. Panel PCB created (UUID1)
2. 6 PCBs copied and translated on UUID1
3. Manufacturing features added on UUID1
4. Window disconnected (EDA window "e7fd83fa..." disconnected)
5. Auto-retry triggered (LSN-20251111-003) - succeeded on new window ID
6. **But the new window context pointed to a DIFFERENT PCB document (UUID2)**
7. UUID2 only had fiducials/outline (1 Pad, 1 Region) - the 6 copies were on UUID1
8. Repour found 0 copper pours (they were on UUID1)
9. DRC passed on empty document

## Root Cause Analysis

### Identified Cause
**Bridge window rotation does not preserve document context.** The `/eda-windows` endpoint returns a new `activeWindowId`, but the bridge executor doesn't track which document was active before rotation. The new window may have a different active document.

### Classification
- [ ] Incorrect assumption
- [x] Missing documentation (bridge window rotation behavior undocumented)
- [ ] API incompatibility
- [ ] Implementation defect
- [x] Engineering mistake (assumed document persistence across rotation)
- [ ] Validation failure
- [ ] Environmental problem
- [ ] Resource/performance limitation
- [ ] Unknown cause

### Why the Original Approach Failed
The retry logic (LSN-20251111-003) only handles window ID rotation, not document context preservation. The bridge doesn't provide a way to "resume" on the same document after rotation.

## Engineering Learning

### What This Failure Taught You
Window rotation is not just a connection issue - it's a **session continuity failure**. The EasyEDA bridge creates a new window context that may not have the same active document.

### Why Original Approach Failed
Assumed window rotation = same session. Reality: new window = potentially new document context.

### What Should Have Been Done Differently
Track the target document UUID explicitly. On rotation, re-open the specific document UUID before retrying.

### Missing Information
Bridge API for listing all open documents or finding document by UUID on new window.

### Early Warning Signs
- Window rotation during multi-step operations
- Operations that create/modify documents across multiple bridge calls

### Future Prevention
**Rule:** For long operations, explicitly track and re-open target document UUID after any window rotation.

---

## Prevention Strategy

### Preventive Rule/Procedure
```
BRIDGE_DOCUMENT_CONTINUITY:
1. Before long operation: record target document UUID
2. On window rotation: re-open target UUID before retry
3. Add document UUID to bridge executor context
4. Verify document type matches expected after rotation
```

### Implementation in DESK
Update `bridge_executor` to:
- Accept optional `document_uuid` parameter
- On rotation: re-open `document_uuid` before retry
- Store `last_document_uuid` in session state
