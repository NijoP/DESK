## What happened
1. `route.py` reported "No compatible Freerouting engine found" because `library/tools` of this DESK checkout was empty.
   A download of the JAR was denied by the sandbox. The JARs were already present in the sibling install
   `C:\Users\HP\OneDrive\Documents\DESK\library\tools` (freerouting 2.0.1 / 2.2.4 / 2.4.1 / 2.5.0 / freerouting.jar) and were copied locally.
2. The first BALANCED run timed out at 300 s with 108 of 320 connections unrouted. The EasyEDA DSN export carries no copper
   pours, so Freerouting routed every GND and 3V3 pin as a trace on a 30 x 45 mm board whose bottom side is mostly the
   ESP32-S3 module. Pass results flattened at ~108 unrouted from pass 18 onwards (stagnation, not a time problem).

## Lesson
- A board with a plane stackup must tell the router about the planes: placement.json now carries
  `"planes": [{"net","layer","polygon_mm"}]` and route.py writes them into the DSN `(structure)` as `(plane NET (polygon LAYER 0 ...))`.
  The polygon must match the real pour (antenna zone excluded) so plane-access vias land on copper.
- Keep the Freerouting JARs in every DESK checkout's `library/tools`; the engine lookup is per checkout.
- Watch the per-pass "N unrouted" line in `state/route/freerouting.log`; a flat curve means change the problem, not the timeout.

## Addendum 2026-11-11 23:05 (attempts 2-4 plateau at ~32-45 unrouted)
- **Placement keepouts are not routing keepouts.** route.py exported every placement keepout as a `(keepout "..." (polygon signal ...))`,
  i.e. an all-layer no-go. The mic-port zones (+/-1.2 mm) contain every pad of the three MEMS mics, and the antenna zone contained
  U5 pads 1/40, so 20 pads were unreachable ("maze search algorithm could not be created", ~20 per pass). placement.json now carries
  `route_keepouts` (antenna cut to y <= 7.5 mm, holes, rounded-corner squares); route.py prefers it.
- **Freerouting 2.1.0 ignores the per-run freerouting.json and -mp.** It loads `%TEMP%\freerouting\freerouting.json`
  (job_timeout 12:00:00, max_passes 9999), so it never stopped by itself and the orchestrator's kill at timeout destroyed the
  best board before the SES was written. The global file now has job_timeout 00:13:00 / max_passes 45 (backup kept next to it)
  and the orchestrator waits 120 s past its own budget so the engine can finish and write the SES.
- Freerouting 2.2.4 / 2.4.1 / 2.5.0 JARs in library/tools need a newer Java than the installed OpenJDK 23 (class version 69 = Java 25).
