## Context
Previous sessions (Nemotron) tried to build a 6-up panel by creating PCB documents and translating primitives (40 PCB docs + 7 blank Panel docs were left in the project). The native EasyEDA Pro mechanism was never used.

## Root causes found this session
1. **Wrong mechanism.** EasyEDA Pro stores panelisation as a `PANELIZE` record inside the PCB document (`on,row,column,rowSpacing,columnSpacing,onlyOutline,horizontalStamp,verticalStamp,horizontalSize,verticalSize`). Tools → Panelize edits this record; Gerber export then emits RS-274X step-and-repeat (`%SRX<c>Y<r>I<w>J<h>*%`). No primitive duplication is required or appropriate. The forensic signature of the failure was exactly this record left at `on:false,row:1,column:1`.
2. **No API for Panelize.** `eda.*` exposes no panelize method; the `PANELIZE` record is only reachable through the dialog (or `sys_FileManager.setDocumentSource`, not used). Human-in-the-loop dialog entry + API readback is the deterministic path.
3. **`onlyOutline` trap.** The dialog's "Panelize Type" defaults to *Only BoardOutline*; the first application left `onlyOutline:true` although the dropdown looked selected. Readback of the record caught it before export; second pass set `false`. Never trust the dialog — read the record back.
4. **Desktop automation unsafe while the Captain is on the desk.** The terminal app re-takes foreground after every tool call; synthesized clicks landed in the terminal. Rule: no mouse/keyboard events unless `GetForegroundWindow()==EasyEDA` *at send time*, and prefer Captain-driven dialogs with API verification.
5. **Foreign artefact in the master.** A 1000×1000 mil Top-layer rule region (`808aedefa6070836`) existed in PCB1 but not in the 2026-11-06 archive — a leftover from an earlier agent. It lies outside the board outline; left in place pending Captain decision.
6. **`dmt_Pcb.modifyPcbName` is unsafe.** First call returned `true` but renamed a *different* PCB (the old PCB1_2) instead of the uuid passed; the retry then failed with "Duplicated pcb title!". Track copies by uuid, never rename via API.
7. **Netlist DRC item is designator-prefix drift.** Schematic C101…U109 vs PCB C301…U309 (identical 22-part set). Not renumbered; not a geometric violation; disappears on an unbound copy.

## Preventive lessons
- Panelisation = PANELIZE record + SR Gerber. Verify with (a) record readback, (b) Gerber `%SR` header, (c) drill hit count = instances × vias.
- Checkpoint every mutation in `output/<release>/00_CHECKPOINTS.md`; idempotent copy guard (check name/uuid before `copyPcb`).
- Independent Gerber check (gerbonara) does not expand `%SR`; expand or count block contents × instances.
