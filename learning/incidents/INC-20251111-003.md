# INC-20251111-003

## Metadata
- **Date/Time:** 2025-11-11 15:45 UTC
- **Project/Task:** 6-up Sensor PCB Panelisation - PCB copy and translation
- **Subsystem:** easyeda-integration / bridge-reliability
- **Severity:** CRITICAL
- **Status:** RECOVERED

---

## Context
**What were you trying to accomplish?**
Copying the master PCB 5 times and translating each copy to its panel position (2×3 grid). Each copy operation involves: `dmt_Pcb.copyPcb()` → open copied PCB → translate all primitives (components, tracks, vias, pours, regions) by X/Y offset.

---

## Expected Behaviour
**What should have happened?**
All 5 PCB copies created and translated successfully. Bridge connection remains stable throughout the ~3 minute operation.

---

## Actual Behaviour
**What actually happened?**
After ~2 minutes and ~20 successful bridge calls, the EDA window disconnected:
```
HTTP 500: {"success":false,"error":"EDA window \"8a96ca83-cf64-45ef-98e3-130fb14ebe66\" disconnected"}
```

The bridge server lost connection to the EasyEDA client. Subsequent calls failed until a new window was detected.

---

## Error Evidence
```
[BRIDGE] HTTP 500, timeout=30, attempt=1
[BRIDGE] HTTP ERROR: 500 - {"success":false,"error":"EDA window \"8a96ca83-cf64-45ef-98e3-130fb14ebe66\" disconnected"}
```

Window ID changed from `8a96ca83-cf64-45ef-98e3-130fb14ebe66` to `1ba4af3d-d52c-4fa5-b389-045ababe5e0c` after disconnection.

---

## Root Cause Analysis

### Identified Cause
**Long-running bridge sessions trigger EasyEDA client disconnects.** The WebSocket connection between EasyEDA extension and bridge server has an idle timeout or the EasyEDA client explicitly disconnects after sustained API activity.

### Classification
- [ ] Incorrect assumption
- [x] Missing documentation (disconnect behavior undocumented)
- [ ] API incompatibility
- [ ] Implementation defect
- [ ] Engineering mistake
- [ ] Validation failure
- [ ] Environmental problem
- [ ] Resource/performance limitation
- [x] Unknown cause (hypothesis: WebSocket heartbeat/timeout)

### Why the Original Approach Failed
No reconnection logic in bridge executor. Assumed persistent connection for entire panelisation workflow (~3-5 minutes).

---

## Recovery

### Attempts Made
| Attempt | Action | Result |
|---------|--------|--------|
| 1 | Retry same call immediately | FAILED (window disconnected) |
| 2 | Query `/eda-windows` for new active window | SUCCESS (new window detected) |
| 3 | Re-execute with new windowId | SUCCESS |

### Successful Solution
**Implement automatic window detection and retry in bridge executor:**
1. On 500 error with "disconnected" message
2. Query `/eda-windows` for new `activeWindowId`
3. Retry with new `windowId` parameter
4. Max 2 retries

### Verification Evidence
After implementing retry logic in `bridge_executor()`:
- Disconnection detected
- New window ID acquired: `1ba4af3d-d52c-4fa5-b389-045ababe5e0c`
- Subsequent calls succeeded with new window ID

---

## Engineering Learning

### What This Failure Taught You
Bridge connections are not persistent. EasyEDA client can disconnect during long operations. The bridge executor must handle window rotation transparently.

### Why Original Approach Failed
No heartbeat, no reconnection logic, no window ID refresh. Assumed single window ID for session lifetime.

### What Should Have Been Done Differently
Implement resilient bridge executor from start with:
- Window ID auto-discovery per call
- Retry on disconnect
- Explicit window selection for long sessions

### Missing Information
EasyEDA bridge WebSocket timeout values and disconnect triggers are undocumented.

### Early Warning Signs
- Operations > 60 seconds
- Multiple sequential bridge calls
- No explicit keep-alive

### Future Prevention
**Rule:** Every bridge call must tolerate window rotation. Never cache window ID across calls.

---

## Prevention Strategy

### Preventive Rule/Procedure
```
BRIDGE_RESILIENCE_RULES:
1. Auto-discover windowId on each call (or cache with 30s TTL)
2. On 500 + "disconnected": query /eda-windows, retry once
3. Max 2 retries per operation
4. Log window rotation events
5. For long ops: explicitly select window via /eda-windows/select
```

### Implementation in DESK
Updated `bridge_executor()` in `tools/panelise_sensor.py` with:
- `max_retries` parameter
- Auto-retry on disconnect error
- Window ID refresh via `/eda-windows`
