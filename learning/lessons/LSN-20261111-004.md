# LSN-20261111-004

## Title
Why PCB routing failed on WATCH rev B (30 x 45 mm ESP32-S3 wearable) and what DESK must change to route a C2/C3 ESP32 board in 90 minutes

---

## Summary
**An autorouter can only succeed when the problem handed to it is complete (planes, outline, true keep-outs) and when its best-effort result can always be brought back into the editor; DESK violated both, so 3 h of routing produced zero tracks in EasyEDA.**

## The Lesson

### Principle
Routing is an information problem before it is an algorithm problem. The DSN handed to the engine must contain (1) every copper plane that exists on the real board, (2) one closed board outline, (3) only keep-outs that are true routing obstacles, and (4) a stop condition that returns the best board. Each missing item alone was enough to make the WATCH job fail.

### Why It Matters
- **Root cause 1 - no planes in the DSN (attempt 1).** EasyEDA's DSN export carries no pours. Freerouting therefore tried to route every GND and 3V3 pin as a trace on a board whose back is 60 % ESP32 module. 108 of 320 connections stayed open. Cost: 20 min plus diagnosis.
- **Root cause 2 - placement keep-outs exported as all-layer router keep-outs (attempts 2 to 4).** The mic-port zones (+/-1.2 mm) and the antenna zone were written as `(keepout (polygon signal ...))`. All 18 pads of the three MEMS mics and two module GND pads sat inside them, so 20 connections were impossible by construction (engine log: "maze search algorithm could not be created"). The router plateaued at 32 to 45 unrouted for three runs (~75 min) while the engineer looked for congestion that was not the problem.
- **Root cause 3 - the engine never returns its best board (attempts 5 to 7).** Freerouting 2.1.0 (the only JAR that runs on the installed Java 23) ignores `-mp`, `router.max_passes`, `autorouter.max_passes` and `job_timeout` in both the per-run and the global `%TEMP%\freerouting\freerouting.json`. It writes the SES only at 100 % routed. The orchestrator killed it at its budget, so boards with 7, 5 and 5 unrouted connections were lost three times (~55 min). 2.2.4 / 2.4.1 / 2.5.0 need Java 25 (class file 69) and fail to start.
- **Root cause 4 - board outline as 36 line segments.** The outline tool drew the rounded 30 x 45 outline as separate `pcb_PrimitiveLine` segments on layer 11. EasyEDA exported a DSN from that twice, then refused ("board outline missing") after a reload. Building a replacement with `pcb_PrimitivePolyline.create` from 36 explicit vertices froze the editor twice; the `"R"` polygon with corner radii creates instantly but exports a skewed boundary. Only the plain `"R"` rectangle is reliable. Cost: ~55 min, two force-restarts, one lost top-layer pour.
- **Root cause 5 - environment drift.** The Freerouting JARs were missing from this checkout (present in a sibling OneDrive checkout); the sandbox denied the download; a low-memory event killed a run; EasyEDA window ids rotated on every reconnect; the greedy passive placer is not run-to-run deterministic, so regenerating the plan without re-placing silently desynchronises plan and board.
- **Root cause 6 - the layout itself.** Even with everything above fixed, 5 connections remain. Through-hole walls (USB-C shell legs, originally the mid-board 1.27 mm display header), a module covering 18 of 30 mm of the back, and a full-board 3V3 plane on L3 left two routing channels of 5 mm and 2 mm across the middle. The J6 move and the L3 island were the right calls but came 2 h late because the router log does not name nets, and without a SES nothing could be inspected in EasyEDA.

### Correct Behaviour
- Build the DSN from the board model DESK already has: declare `(plane NET (polygon LAYER ...))` for every pour-backed net, exactly where the pour is; write only `route_keepouts`; emit one closed outline. Pre-flight: assert no pad lies inside a router keep-out, exactly one outline primitive exists, planes match pours.
- Run an engine that can stop on a plateau and still return its best board (Freerouting >= 2.4 on Java 25, or Freerouting API mode with job cancel/output, or EasyEDA's native autorouter driven from the GUI). Treat "no SES" as a tool defect, never as a routing result.
- Keep the engine's unrouted list visible per pass and map it to net names (pin index -> DSN pin id -> net) so placement fixes are targeted, not guessed.
- Place for routing from the start: no through-hole barriers across the middle of a small board, planes on inner layers declared from the placement plan, antenna and port keep-outs sized for routing, not just for parts.

### Incorrect Behaviour (Anti-pattern)
- Exporting the board "as is" and blaming congestion.
- Tuning timeouts and pass counts while the DSN is structurally unroutable.
- Killing the engine at a budget without a mechanism that preserves its best board.
- Drawing board outlines as line segments or long vertex polylines through the API.
- Re-running the placement generator after live placement without re-placing.

## Practical Application

### When to Apply
Every DESK routing job, and specifically the C2/C3 ESP32 IoT target: 4 layers, 80 to 120 parts, 300 to 400 connections, 30 x 45 to 60 x 80 mm.

### How to Apply
1. `placement.json` must carry `planes` and `route_keepouts`; `route.py` refuses to run if a pad is inside a router keep-out or if more than one outline primitive exists.
2. The outline step creates one `pcb_PrimitivePolyline` from an `"R"` polygon; rounded corners are represented by corner keep-outs for routing and by the fab outline drawn once in the GUI until a verified arc polygon format exists.
3. Engine discovery must prove the JAR starts on the installed Java and must prove the stop condition works (a 2-pass smoke run that produces a SES) before any 15-minute run.
4. Orchestrator: stop on plateau (no improvement for N passes) and always collect the SES; on timeout, request a graceful stop (API cancel) and collect the SES.
5. Per-pass telemetry: unrouted count and net names into `state/route/progress.json`; the Captain sees progress without reading a 700 MB engine log.
6. Fallback: if the engine cannot return a SES, hand the job to EasyEDA's native autorouter (GUI, Captain-driven) rather than re-running.

### Verification
- Pre-flight report shows `pads_in_router_keepouts = 0`, `outline_primitives = 1`, `planes = <pours>`.
- Smoke run returns a SES in under 2 min.
- A routing job either ends with 0 unrouted or with a SES whose open nets are listed by name.

### Budget to meet the 90-minute routing target
| Step | Budget |
|---|---|
| Pre-flight (planes, outline, keep-outs, smoke run) | 5 min |
| Engine run 1 with plateau stop | 20 min |
| Import, connectivity report with net names | 5 min |
| Targeted placement fix for named nets, re-run | 30 min |
| DRC convergence on routed copper | 20 min |
| Reserve | 10 min |

## Prevention Rule

### Rule Statement
**ROUTE_INPUT_COMPLETE_AND_RESULT_ALWAYS_RETURNED:** DESK never starts a long routing run unless the DSN pre-flight passes (planes declared, one outline, no pad inside a router keep-out) and the engine has demonstrated, on the same host, that it returns a SES when stopped.

### Implementation in DESK
- `tools/route.py`: pre-flight gate before Phase 10 (open); `route_keepouts` preferred over `keepouts` (done 2026-11-11); plane injection from `placement.json` (done); `--reuse-dsn` (done).
- `desk/routing/orchestrator.py`: grace period after budget (done); `TIMEOUT_PARTIAL` status (done); per-run `router.max_passes` key (done, ineffective on 2.1.0); add smoke run and plateau stop with SES collection (open).
- `library/tools`: ship a Freerouting build that honours max passes on the installed Java, or pin Java 25 (open).
- Outline step: single `"R"` polyline (done for rev B); arc-capable polygon format to be verified (open).
- Tests: `tests/test_route_preflight.py` for the three pre-flight assertions (open).
