## The Lesson

### Principle
The EasyEDA bridge WebSocket connection between the extension and bridge server is not persistent. After ~60-120 seconds of sustained API activity, the EDA client disconnects and reconnects with a new window ID. Code that caches window IDs fails with "EDA window disconnected" errors.

### Why It Matters
Long-running engineering operations (panelisation, batch placement, Gerber export, DRC on large boards) will fail unpredictably without transparent reconnection handling. Silent failures corrupt engineering workflows.

### Correct Behaviour
```python
def bridge_executor(js_code: str, window_id: str = None, timeout: int = 60, max_retries: int = 2) -> dict:
    """Execute with automatic window rotation handling."""
    for attempt in range(max_retries + 1):
        # Auto-discover window if not provided
        if window_id is None:
            window_id = get_active_window_id()
        
        payload = {"code": js_code}
        if window_id:
            payload["windowId"] = window_id
        
        response = requests.post(BRIDGE_URL, json=payload, timeout=timeout)
        data = response.json()
        
        if data.get("success"):
            return data.get("result", {})
        
        error = data.get("error", "")
        if "disconnected" in error.lower() and attempt < max_retries:
            # Window rotated - discover new one and retry
            window_id = get_active_window_id()
            time.sleep(2)
            continue
        
        return {"error": error, "ok": False}
    
    return {"error": "Max retries exceeded", "ok": False}
```

### Incorrect Behaviour (Anti-pattern)
```python
# BAD: Caches window ID, no retry
WINDOW_ID = get_active_window_id()  # Once at startup

def bridge_executor(js_code: str) -> dict:
    payload = {"code": js_code, "windowId": WINDOW_ID}
    response = requests.post(BRIDGE_URL, json=payload, timeout=60)
    return response.json().get("result", {})
# → Fails after ~2 minutes with "EDA window disconnected"
```

## Practical Application

### When to Apply
- Any bridge call sequence >30 seconds
- Batch operations (copy 5+ PCBs, place 50+ components)
- Gerber/NC drill export
- DRC on panels >2 boards
- Any automation running unattended

### How to Apply
1. Never cache window ID globally
2. Auto-discover on each call or use short TTL (30s)
3. Implement retry with exponential backoff (2s, 4s)
4. Max 2 retries per operation
5. Log window rotation events for debugging

### Verification
- 10-minute panelisation run completes without manual intervention
- Window rotation logged but operation succeeds
- No "EDA window disconnected" errors reach caller

---

## Prevention Rule

### Rule Statement
**BRIDGE_WINDOW_RESILIENCE:** Every bridge executor must handle window rotation transparently. No global window ID caching. Auto-retry on disconnect (max 2). Log rotation events.

### Implementation in DESK
- `tools/panelise_sensor.py::bridge_executor()` updated with retry logic
- `desk.adapters.easyeda_pcb_adapter.EasyEDAPcbAdapter` needs same resilience
- `desk.bridge` module (core) should provide resilient base class
- Add integration test: 5-minute sustained bridge session
